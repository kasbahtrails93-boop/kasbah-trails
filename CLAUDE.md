# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Kasbah Trails is the marketing site for a boutique private Morocco tours business, built as a Next.js 16 (App Router) + Tailwind CSS v4 + TypeScript project. It started life as a single self-contained static HTML file (`kasbah-trails.html`, still present in the repo root for reference/history — not part of the live site) and was rebuilt into this app.

## Commands

- `npm run dev` — start the dev server (Turbopack, default port 3000)
- `npm run build` — production build (also type-checks; fails the build on TS errors)
- `npm run lint` — ESLint (flat config)
- `npm start` — serve the production build

There is no test suite.

## Architecture

- Imports use the `@/*` path alias (`tsconfig.json`) mapped to `./src/*`, e.g. `import { TOURS } from "@/lib/data"` — used throughout instead of relative `../../` paths.
- `src/lib/data.ts` — **the single source of truth for tour content**: `TOURS` (33 tour objects — routing, `days`, `cat`, `blurb`, `highlights`, and a full day-by-day `itin` array), `CONTACT`, `INCLUDED`/`EXCLUDED`, `DEST` (destinations grid), `REVS` (testimonials), `TINT` (per-origin-city color pairs, a leftover from the removed SVG art; since the `Why` rebuild nothing imports it).
- `src/lib/blog.ts` — the 20-post blog: each post has `scene`/`origin` (for photo picking), `intro`, and a `blocks` array (`h2`/`p`/`ul`) rendered by `BlogBlocks`. Body text supports inline `[label](url)` markdown-style links (parsed by `RichText`/`renderRich`) — internal paths render as `next/link`, external ones as new-tab anchors. `related: string[]` on each post drives the "Related reading" block.
- `src/lib/photoPool.ts` — **the real-photo system**. `pickPhoto(scene, seed)` deterministically (hash of `seed`, e.g. a tour id or post slug) picks a photo from a themed pool (`dunes`/`medina`/`coast`) so every tour card, tour page, and every blog card/post consistently show the same real photo across renders — not a unique photo per item (there aren't 33+20 unique curated shots), a themed pool reused sensibly. The 12 pool photos are drawn from `public/images/hero/`, `destinations/`, and `pool/` (the last holds only the extras not used elsewhere). `SceneSvg` (the original procedural-illustration system) was removed once cards moved to real photos; `Why.tsx` uses a single static captioned photo.
- `src/lib/places.ts` — one real photo per named place (`PLACES`, each with a `match` regex of the spellings used in itinerary day titles). `tourPlaces(tour)` returns the places a tour's day titles/highlights actually mention, in itinerary order — it drives the tour page's route line and dark "places on this route" strip, so a tour never shows a place it doesn't visit. `src/lib/destinations.ts` holds `DEST_DETAIL` (long descriptions), `destSlug` (anchor ids on `/destinations`, used by footer links) and `toursVisiting(name)` (the "On N routes" badge — every itinerary genuinely passes Aït Ben Haddou and the Sahara, so those read 33).
- Homepage sections live in `src/components/home/`. `LuxuryHero.tsx` is the full-screen 4-slide hero (Kasbah / Sahara / Marrakech / Escape; per-slide copy, focal point and CTA): crossfade + slow zoom, staggered `.hero-in` copy, autoplay driven by the `hero-progress` CSS animation on the progress line (pausing hover/focus pauses it; `onAnimationEnd` advances), prev/next + thumbnails + swipe + ArrowLeft/Right, reduced-motion aware, only current + next photos mounted. On `/` the `Header` is `fixed` and transparent over it (turns paper-white after 40px scroll); everywhere else it stays sticky and solid. `WhatsAppFloat` hides on the homepage until past the hero.
- `src/components/TrustStrip.tsx` — four facts with line icons (100% private, 33 itineraries, 4 start cities, honest pricing) under the journey finder and on `/about`.
- `src/components/ToursSection.tsx` — the filterable catalogue on `/tours`: underlined style tabs (the three `cat` values) plus "Starting from" and "Trip length" selects, and a live count. `initialCity`/`initialCat`/`initialLen` come from `/tours?city=&cat=&len=` (Next 16's async `searchParams`); unknown values and `all` mean no filter, which is what `JourneyFinder` relies on. `FeaturedTours.tsx` shows six on the homepage, picked so each shows a different photo. All use `TourCard` (whole card clickable, style tag + days tag on the photo, route line, "View journey"), which links to `/tours/[id]` — there is no modal.
- `src/app/tours/[id]/page.tsx` — **every tour's real, indexable page** (`generateStaticParams` over all 33): full-width photo header (breadcrumb, category, H1, fact chips) → sticky in-page section bar (Overview / Itinerary / What's included / Questions + enquire button) → main column: blurb, highlight tiles, "The route" as a line of photo stops (from `tourPlaces`), a day-by-day timeline where a day gets a small framed photo only when it first reaches a photographed place (`dayPlace`), included/not-included panel, route FAQs (from `FAQS` in `Faq.tsx`); sticky "Plan this journey" sidebar with facts and a compact `ContactForm tourTitle=…` → related tours → `CtaBand`. On phones a fixed `.tour-bar` (days + Enquire) stays at the bottom; `globals.css` pads `body` and lifts the WhatsApp button when it's present. Everything but the form is server-rendered. Own title/description/canonical metadata and `TouristTrip` + `BreadcrumbList` JSON-LD. This replaced a client-side `TourModal` whose content was invisible to search engines; confirm it hasn't regressed with `curl <url> | grep "Day by day"` on a `/tours/<id>` page if touching this area again.
- `src/components/BlogCard.tsx` / `BlogBlocks.tsx` / `TableOfContents.tsx` — blog rendering. `TableOfContents` auto-generates from a post's `h2` blocks (via `slugify` in `src/lib/slugify.ts`) and only renders when a post has 2+ headings; `BlogBlocks` gives each `h2` a matching `id` + a `scroll-mt` of the header height so the anchors land below the fixed header.
- The brand mark is a real logo (`public/images/brand/kasbah-trails-mark.png`, cropped from a supplied source image), shown in the header/footer through `BrandLockup.tsx` (mark + "Kasbah Trails" wordmark + "Private Morocco Tours" tagline; the mark itself is never recoloured) and via plain `next/image` in the blog byline. `src/app/icon.png` is a separate square crop of the same source, used as the favicon/app icon.
- `src/components/Breadcrumbs.tsx` — used on `/tours`, `/tours/[id]`, `/blog`, every blog post, and `/contact` (also emitted as `BreadcrumbList` JSON-LD on tour and blog post pages).
- `src/lib/wa.ts` — `waLink(text)` builds `https://wa.me/...` deep links; every CTA site-wide funnels through this. `src/components/Contact.tsx` is the "Not sure which journey fits?" band under `/tours` (it also exports `CONTACT_POINTS` and `DirectContact`, reused on `/contact`). `src/components/ContactForm.tsx` is the real multi-field form — a card on `/contact`, `compact` + `tourTitle` in the tour sidebar. It has no backend: on submit it builds a message from the fields and opens WhatsApp client-side. `CtaBand.tsx` is the closing panel on most pages (contained split card: photo beside a kasbah-brown invitation with buttons and phone/email).
- `src/app/layout.tsx` — root layout: fonts (Marcellus for headings, Jost for everything else, via `next/font/google`), metadata (with `alternates.canonical: "/"`), `TravelAgency` + `FAQPage` JSON-LD, a skip link, `<main id="main">`, and the global `Header`/`Footer`/`WhatsAppFloat`/`BackToTop`. The header is a solid paper-white **sticky** bar (never overlaid on a hero): logo lockup, uppercase nav (Tours, Destinations, About, Contact; the journal is linked from the footer), a "Speak to us" phone line at `xl`, and a terracotta "Plan your journey" button; below `lg` it opens a menu sheet rendered outside `<header>` (the header's `backdrop-filter` would otherwise become the fixed sheet's containing block). Internal nav links must be root-relative with a leading `/` (e.g. `/#faq`) and use `next/link`. "How it works" (`Process.tsx`, `id="how"`) and "FAQ" (`Faq.tsx`, `id="faq"`) are homepage sections reached from the footer.
- Every listing/detail page (`/tours`, `/blog`, every `/blog/[slug]`, every `/tours/[id]`, `/contact`) sets its own `alternates.canonical` — needed because `/tours` gets linked with `?city=`/`?len=` query strings all over the site (footer, blog posts) and those must all canonicalize to the plain `/tours`, not fragment as separate indexable URLs.
- Routes: `/` (`src/app/page.tsx`: `LuxuryHero` → `Intro` (framed photo with overlaid pull quote + team sign-off) → `Journeys` (chips + `Rail` carousel of tour cards; server builds itinerary-free data) → `TravelYourWay` → `Experiences` (real highlights, verified against `TOURS`) → `Values` → `Destinations` (the kept horizontal `DestinationPanels`) → `Steps` (light split: sticky heading/photo/CTA beside a vertical timeline of step cards) → `Voices` (placeholder reviews, flagged) → `Guides` (journal `Rail`) → `Questions`) → tabbed signature journeys (`FeaturedTours.tsx` picks the tours server-side and passes itinerary-free `TourSummary` data to the client `FeaturedJourneys.tsx`: one large lead journey + three cards per tab) → `CinematicBreak` (full-width road photo with a CSS scroll-driven `.drift`, one line of type) → `SignatureExperiences` (real itinerary highlights, each verified against `TOURS` and linked to its tour) → dark "why travel with us" band → `Destinations` as `DestinationPanels` (desktop: hover/focus/tap opens one tall panel and folds the rest into labelled strips; phones: swipeable snap row) → `WhenToGo` seasons (wording kept to the FAQ's own season answer) → process timeline → dark one-at-a-time reviews → journal (lead guide + list) → FAQ → `CtaBand`). Section headings fade up on scroll via the CSS-only `.reveal` class (scroll-driven, off for reduced motion), `/tours` (dynamic due to `searchParams`), `/tours/[id]` (33 static params), `/blog` (listing, with `ItemList` JSON-LD), `/blog/[slug]` (20 static params, each with `Article` + `BreadcrumbList` JSON-LD), `/destinations` (dark hero with story, counts and a four-photo mosaic → sticky `DestinationNav` of place chips with scroll-spy → lead `DestinationCard` wide, the other eight in two columns; each card lists three real tours from `toursByDestination`, which avoids repeating tours across cards → closing "build your route" panel), `/about`, `/contact`, plus `not-found.tsx`. Listing pages open with `PageHero.tsx` (photo banner, left-aligned breadcrumb + label + title + intro). Plus `src/app/sitemap.ts` (lists all of the above, not `/preview`) and `robots.ts`.
- `src/app/preview/page.tsx` — a `robots: { index: false, follow: false }` scratch page (banner: "Style refresh preview... Not live") exploring an alternate, flatter visual style (border cards instead of shadow cards, `rounded-lg` not `2xl`/`3xl`) using its own standalone `src/components/preview/HeroSlider.tsx`, not the real `HeroSlider`. It's not linked from any nav and isn't part of the live site — don't treat it as dead code to delete, and don't confuse it with the real homepage sections it mimics.
- shadcn/ui is scaffolded (`components.json`, `src/components/ui/button.tsx`, plus the `@base-ui/react`, `class-variance-authority`, `cn`, `lucide-react`, `tw-animate-css` deps) but not wired into any live page yet — no current component imports `Button` or `cn`. `embla-carousel-react` and `motion` are also installed but currently unused. Treat these as available scaffolding for future UI work (e.g. the `/preview` restyle), not things to rip out.
- Brand tokens are CSS custom properties in `src/app/globals.css`, exposed to Tailwind via `@theme inline`, and **taken from the logo's own colours**: `paper` (page), `sand`/`dune` (alternate grounds), `card`, `ink`/`body`/`muted` (text), `kasbah`/`kasbah-2` (dark sections and footer — warm brown, never black), `rust`, `terra`/`terra-d` (the action colour: buttons, links), `sun`/`sun-d` (logo sun gold: labels and detail on dark grounds), `palm` (logo palm olive: small tags), `line`/`line-dark`. Plus the type scale (`text-display`/`h1`/`h2`/`h3`), `container-site` (1240px), `section-y` (padding-block: `var(--sy)`; when two light sections sit back to back, give the second `pb-[var(--sy)]` only so the gap doesn't double), `eyebrow` utilities, and component classes `.btn` + `.btn-primary`/`.btn-dark`/`.btn-ghost`/`.btn-light`/`.btn-outline-light`/`.btn-sm` (squared, tracked uppercase), `.card` + `.card-hover`, `.tag`, `.field`, `.link-arrow`, `.zoom`, `.zellige` (faint lattice for dark sections only). `Ornament.tsx` exports the eight-point zellige `Star` and a star-on-rule divider used under centred headings. **Custom base styles (e.g. the `h1`–`h4` rule) must stay inside `@layer base`** — Tailwind v4 utilities live in a cascade layer, and an unlayered rule always beats a `text-*` utility (this once made white headings on dark backgrounds render dark-on-dark). The neutral `oklch` tokens in the same `:root` belong to the unused shadcn scaffold.
- `public/images/` — only the curated, renamed photos actually used by the site (`hero/`, `destinations/`, `pool/` and `brand/` for the logo mark). The original 400+ file raw image dump lives in `images/` at the repo root and is git-ignored — it's a source pool to pick further real photos from if the existing pool ever needs more variety, never referenced directly by the app.

## Editing conventions to preserve

- Visual direction: an original Kasbah Trails design. The owner pointed to moroccotailoredtours.com as a reference for what a professional operator site offers (clear journeys, filters, per-tour enquiry, trust signals) but explicitly **does not want its template or style copied** — keep this site's own identity: the logo's colours, Marcellus/Jost, photographs set in an offset gold hairline frame — no arch-shaped frames anywhere, the zellige star, warm-brown dark sections, squared buttons. Don't copy text from reference sites.
- Section labels go through `Eyebrow.tsx` (star + tracked caps) / `SectionHeading.tsx` (centred with the star rule, or left-aligned). Numerals are used only for real sequences (itinerary days, the four `Process` steps). Keep light (`paper`/`sand`) and dark (`kasbah`) sections alternating.

- Add/edit tours by editing `TOURS` in `src/lib/data.ts`; add/edit posts by editing `BLOG` in `src/lib/blog.ts`. Both are JSX-rendered, not `innerHTML` — no HTML entities in strings.
- Every card/modal/post that needs an image should go through `pickPhoto(scene, seed)`, not a new one-off `<Image>` — this keeps art consistent and avoids re-curating photos per item. Only add a new photo to `photoPool.ts`'s pools if the existing 12 genuinely don't fit a new scene.
- `CONTACT.phoneDisplay`, `CONTACT.phoneTel`, and `CONTACT.wa` in `src/lib/data.ts` are placeholders that must be replaced with the real business phone/WhatsApp number before launch.
- `REVS` entries are explicitly placeholder reviews — flagged as such in the rendered page — until replaced with real, sourced ones.
- Blog post bylines are an honest organizational credit ("Written by the Kasbah Trails team"), deliberately not a fabricated named author with a headshot — keep it that way unless a real, named writer exists.
- Any new local image goes in `public/images/...` with a descriptive, kebab-case, SEO-friendly filename (not a stock-photo ID) and a specific `alt` string — never reference the raw `images/` dump directly.
- Blog post `title` should read naturally as the on-page H1 even if long; if it's north of ~60 characters, add a shorter `metaTitle` (used only for the `<title>`/`og:title` tag) rather than shortening the H1 itself — Google truncates the rendered `<title>` (post title + " | Kasbah Trails") around that length, but a longer, fuller H1 has no such penalty.
- When a blog post names one specific tour by its exact spec (e.g. "our 7-day Sahara desert tour from Marrakech"), link it straight to that tour's `/tours/[id]` page, not a `/tours?city=&len=` filtered listing — check the `len=` bucket actually contains that tour's day count before ever linking a filtered listing for a specific-sounding claim (a past bug: "10 and 12-day grand tours" linked to `len=8-11`, which excludes every 12-day tour).
- Avoid repeating the same rhetorical device (an exact H2 wording, a stock opening line like "Worth it, with a caveat") across more than one post — it reads as templated when posts are read back to back. Keep intensifiers ("genuinely", "honestly", "actually") sparing; they're fine used once or twice across the whole file, not once or twice per post.
